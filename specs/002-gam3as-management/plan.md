# Implementation Plan: Gam3as Management

**Branch**: `002-gam3as-management` | **Date**: 2026-04-04 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/002-gam3as-management/spec.md`

## Summary

Replace the Phase F1 Gam3as stub screen with a full CRUD interface: a scrollable list of Gam3a cards (US1/P1), an add form (US2/P1), an edit form (US3/P2), and swipe-to-delete with confirmation (US4/P2). All data flows through the existing Django B1 REST API (`/api/gam3as`). No backend changes are required. The feature follows the same repository → Riverpod provider → ConsumerWidget pattern established in Phase F1.

## Technical Context

**Language/Version**: Dart 3.x · Flutter 3.x (stable channel)
**Primary Dependencies**: flutter_riverpod ^2.5.1 · riverpod_annotation ^2.3.5 · go_router ^14.0.0 · dio ^5.4.0 · intl ^0.19.0 (all already in pubspec.yaml — no new packages needed)
**Storage**: SharedPreferences for list cache (same pattern as SimulationResult cache in F1)
**Testing**: flutter_test · mocktail ^1.0.4 · riverpod_generator ^2.4.0
**Target Platform**: Web (Chrome) · iOS · Android (single Flutter codebase)
**Project Type**: Mobile + Web app (cross-platform Flutter client)
**Performance Goals**: List loads within 2 s (SC-001); dashboard refresh within 1 s after any mutation (SC-003)
**Constraints**: No new pub.dev packages; no platform-specific code; zero inline hex colors; all money as int piastres
**Scale/Scope**: <50 gam3as per user; no pagination required

  core/

test/
  features/
    gam3as/
      gam3a_test.dart                   # fromJson/toJson round-trips (≥6 cases)

**Structure Decision**: Feature-module layout under `lib/features/gam3as/` matching the F1 convention for `simulation/`. The form screen is a full-screen GoRouter route pushed on top of the `ShellRoute` (not inside the nav shell), receiving the optional existing `Gam3a` object via `GoRouter` `extra` for edit mode.
